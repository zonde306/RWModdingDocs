# 多层地图 mod：1.7 架构调研

原始方法核对：2026-10-16，RimWorld 1.7.4979 rev109，MVID 425a593954d7432a8f44e3076b25fce9。当前安装已更新至 1.7.4980 rev60；指纹和有限增量复核见 [sources.md](sources.md)。原版事实表保留历史证据范围。

状态：静态调研与设计建议。未创建 mod、未编译实现、未启动游戏验证。下文自拟类名均为建议接口，不是原版 API。

## 调研收口入口

原始需求的证据对照、推荐原型路线、必要不变量和验证范围汇总到 [readiness](multilayer-readiness.md)。当前关键 API 调查已覆盖路径/工作、严格屋顶、战斗、公共系统和任务仲裁；本页保留两种架构的总体设计。静态调查完成不表示 mod 已实现或运行验证通过。

## 结论与范围

已确认两条可行设计路线：一层一张原版 Map，以跨层服务协调转移；或一张扩大的 Map 存放多个楼层坐标带，以路径拼接维持原版 Job。新调查的 [IsoRim ProjectZ / IsoRim Waylith](multilayer-reference-isorim.md) 为后者提供了直接源码参考。针对连续工作和俯射，值得优先验证单 Map 方案；正式选型仍需比较距离搜索、地图生成、渲染和兼容成本。

原版提供多 Map、PocketMap 和 MapPortal，却没有自动跨图工作所需的完整调度语义。多 Map 方案不能只给 CanReach 返回 true，也不能默认给旧 Job 插入一个楼梯 Toil 就能保留执行状态。单 Map 方案避开上下楼的离图清理，但仍需扩展非相邻路径、区域可达性和逻辑空间查询。

建议先做固定对齐的离散楼层。跨层追击后在同层战斗，与跨楼层直接射击，是两个独立里程碑；完整目标应覆盖后者，但不要让弹道阻塞移动和物流验证。

## 架构选择

| 方案 | 代价与取舍 |
|---|---|
| 一层一 Map + 跨层服务 | 层内坐标及管理器自然；需处理调度、转移、地图额度和跨层交互。Baal 样本可参考任务续接。 |
| 一张大 Map 存放多个楼层坐标带 | 同 Map 保留 Job/Driver、物品索引与普通预订；需适配非相邻路径、距离/半径、生成网格、事件边界及绘制。IsoRim ProjectZ 已有源码原型，详见专项。 |
| 将原版地图网格改成真正三维 | 牵涉格子索引、Region、寻路、渲染、序列化和大量二维假设，维护范围最大。 |

下文模块、转移协议及 P0 以一层一 Map 为设计分支，不应作为单 Map 实现的必需流程。单 Map 的普通过层由同一个 Job 的路径执行，不为每个楼梯拆 Job；其生成、选物距离、路径和弹丸存读档验收见 [IsoRim 专题](multilayer-reference-isorim.md)。

固定楼层先共享 x/z 原点与尺寸，独立保存 level；不要把 IntVec3.y 当作原版已支持的层号。逻辑坐标为 (stackId, levelId, x, z)，原版局部格子仍为 (x,0,z)。地图引用、稳定层 ID 与显示层序分别管理，不持久化 Map.Index。

地图生成先做普通持久 MapParent 与 PocketMap 的小原型比较。PocketMap 可提供现成父子关系，但需要审计殖民地身份、故事叙述、天气、袭击、任务、离图与回收语义；不要仅因为有生成工具就直接选定。推荐封装地图创建策略，先验证 Core-only 是否可用，再决定 DLC 支持和依赖。

## 建议模块与数据契约

| 建议模块 | 职责 |
|---|---|
| LayerStackComponent : GameComponent | 楼层注册、图拓扑、跨层任务意图、资源声明；生命周期属于当前存档。 |
| LayerMapComponent : MapComponent | 本层入口、工作候选、储存候选和几何版本；读档后重建派生索引。 |
| CompLayerConnector | 楼梯/梯子/电梯入口及配对出口，方向、耗时、容量、权限与通行能力。 |
| CrossLayerRouter | 输入明确的源地图/格子、目标、Pawn 能力与策略，输出分段路线或失败原因。 |
| CrossLayerTaskCoordinator | 保存任务意图，派发本层 Job，处理取消、重规划、抢占和读档恢复。 |
| TransferService | 唯一跨图转移入口，统一携带物、落点、征召、寻路和通知。 |
| WorkAdapterRegistry | 按工作类别提供远程候选、可执行性、资源需求与抵达后建 Job 的适配器。 |
| CrossLayerCombatService | 跨层目标感知、追击；后续扩展三维视线、射击与爆炸。 |

远程目标可采用 TargetInfo，或自有 LayerTarget：明确包含地图/层引用、格子或 Thing 引用、失效规则。Thing 移动时重新检查 MapHeld 与所有权；纯格子始终带图。不能用同一个裸 LocalTargetInfo 表示两层相同坐标。

任务意图保存 taskId、Pawn/目标引用、工作类别、数量、阶段、失败原因和恢复策略。不要把运行中的 Job/Driver/Toil 深拷贝成第二套执行栈；原版 Job 存在池化及清理流程。

单 Map 的选物、工作台取料、格子工作、放料及动态断路已另行核对当前 1.7.4980，见 [工作查询与动态路径审计](multilayer-queries.md)。已确认原版普通格子扫描的 99999 距离平方上限、账单三处半径过滤，以及连接器删除后当前拼接路径需单独验证的问题；这些不能只靠扩展可达性解决。

## 跨层寻路

连续经过中间层、需求选物/家具/工作台，以及多次往返时的目标保持，详见 [连续跨层寻路与任务协调](multilayer-routing.md)。正常一层→二层→三层保持同一最终任务；本层 Job、路线段与取料等子任务分别管理。专篇记录当前 1.7 的需求入口、自动重新分派、暂停/队列、continuation、预订与读档约束，以及尚待实现的交接协议。

采用分层图搜索：节点是入口/出口端点，跨图边是连接器，同图边由原版可达性与路径成本提供。加入临时起终点，Dijkstra 或有可采纳下界的 A* 搜索，执行时每次仅派发当前地图的一段。

成本为本层行走 + 过层耗时 + 等候估计 + 策略惩罚。不能按“最近楼梯”贪心，也不能只搜索地图相邻关系：同一层的两个楼梯可能被墙隔开，同层目标也可能需要绕到另一层再返回。

先用可达性过滤，再用低成本估计筛少量路线；精算候选路径。估计成本路线不宣称全局最优。若要保证最优，应明确精确边权或下界与后续求精条件。

遍历策略包含危险等级、门/围栏、破门能力、禁区、敌我权限、携带状态、体型和连接器限制。区域可通只作粗筛；各段仍按具体 Pawn 验证。

拓扑/几何/策略变更触发版本失效；缓存键不能只有起终层。出口堵塞、楼梯销毁、电梯断电、目标转移时重新验证及限次重规划。电梯容量和楼梯对向冲突用短时通行声明与排队，等待应可中断，避免永久占用全部入口。

## 转移协议与任务恢复

携物与征召状态、GameComponentTick 转移队列、生成/回收策略及结构楼面细节见 [多层框架落地调研](multilayer-foundations.md)。新增证据表明 carryTracker 不在离图移除列表中，但 pather/drafter 会被重建；Job 两端携物策略仍需显式控制。原版 PocketMap 财富已向 sourceMap 递归汇总，不应再次无条件跨层求和。

推荐状态链：

候选 → 声明资源 → 本层移动 → 等待通行 → 转移 → 抵达校验 → 创建本层 Job → 完成/重规划/取消

转移前先确认目标 Map 已生成、出口仍有效且存在合法落点；失败时尽量留在源图。通过队列或已确认安全的阶段执行转移，避免在将被 DeSpawn 清掉的 Driver 回调内继续启动下一 Job 而产生重入。

允许原版完成正常清理；任务意图保存在协调器中。转移后，在安全的后续阶段重建本层 Job。StopAll、取消、危险抢占和正常过层必须有不同原因标记，避免过层被误判为用户取消，或用户取消后任务被自动复活。

携带物是首要原型门槛：Job 清理可能先放下物品。需要核实并使用本层交接 Job 的 carry 语义，或由可序列化 IThingHolder/ThingOwner 临时接管再归还；统一处理库存、装备、尸体与被救援 Pawn。禁止克隆 Thing 或只改 mapIndex 绕过登记。最终方案以游戏内验证选定。

要求转移幂等、同一实体只有一个所有者；失败回退不能覆盖落点已有物体。源图移除或无法回退时需要明确的持有和安置策略。跨 tick 的转移状态必须能存档；尽量让实际离图/入图提交在同一个受控阶段完成。

征召命令队列应保存为自有意图队列。Lord 通常按地图组织，跨层敌人需要战略目标协调及本层 Lord/Job 的重新归属；宠物、机械控制、牵绳、选中状态也要专项验证，不能照搬原版 portal 的 ExitedMap 语义。

## 资源与预订

仅在自有字典里“锁住远程资源”不够：本层原版 Pawn 仍可能抢到它。建议两层协议：

1. 协调器维护短期资源声明，覆盖物品数量、目标格容量、工作台/交互格与连接器通行。
2. Pawn 抵达后建立本层原版 reservation，随后原子交接声明；失败则释放或重新规划。

声明必须参与相关原版 CanReserve/Reserve 竞争检查，或对目标采用可审计的真实持有方式；同图已有 reservation 也必须阻止新声明。只作用于本 mod 楼层组内活跃声明，保留原版层、数量、派系和多 Pawn 规则。不能伪造远程 claimant.Map 来骗过原版。

多个资源按稳定顺序获取，失败全部撤回，避免循环等待。声明有任务所有者、超时、续期与取消清理；Pawn 死亡/征召/倒地、物品 SplitOff/并堆/销毁、地图移除均使其重新验证。过层会清原版所有地图预订，所以不能依赖跨图提前 Reserve 长期保活。

## 搬运与工作

跨层搬运必须联合选择来源、目的地及完整路线。储存优先级和过滤器先决定是否合法，再按总运输成本比较；显式设计同优先级调拨，防止楼层间来回搬。目标容量、容器接收与源堆数量都要声明，入库时重新检查。

第一版只搬一种物品的一批数量；多堆合并、背包搬运及多目的地路线后续实现。物品堆可能被拆分、吸收或搬走，使用引用与数量校验并能重选，不能永久假设 Thing 引用与 stackCount 不变。

工作发现采用“远程候选适配器 + 抵达后原版复核”。适配器显式接收 Map、预测入口和 Pawn 能力，禁止临时改 pawn.Map/Position、全局 Find.CurrentMap 或生成代理 Pawn 试跑任意 WorkGiver；这些会污染缓存、预订及状态。

保持原版 WorkType/WorkGiver 优先级、技能、时间表与紧急工作语义；在同优先级组比较本层和远程候选。只在闲置时跨层可作为早期模式，但不能称为完整跨层工作调度。前往工作途中允许饥饿、休息和危险抢占，并设置失败退避，防止无效任务往返。

按类别接入：

| 类别 | 建议第一种实现 |
|---|---|
| 清扫、采矿、种植、研究 | 到目标层后复核，创建本层原版 Job；技能、区域、交互格和目标有效性需适配。 |
| 建造、修理 | 区分工作目标与材料供应；先供应目标层，再派发本层 Job。 |
| 制造/烹饪账单 | 第一阶段将所需原料送到目标层可访问储存，再让原版选料及加工；原料可见不等于 JobDriver 能跨层取料。 |
| 救援、医疗、看守、喂食 | 涉及被携带 Pawn、床位、药物、权限与时效，单列适配器和验证。 |
| Mod 自定义 Job | 注册适配器；未支持时保留其本层行为，提供诊断，避免声称任意 mod 自动兼容。 |

最终若要“一张账单的原料散布多层也自动生产”，需要材料需求计划、跨层补给子任务、缺料等待与取消回收；第二阶段才考虑由同一工人跨图连续取料。账单半径要明确是本层几何半径还是跨层运输预算。

## 战斗与空间几何

阶段 A：跨层目标发现、寻路追击和切层征召；到同层后复用原版近战/射击。敌人必须能跟随目标上楼，并处理楼梯阻塞、断路、撤退和 Lord 归属，避免上层成为永久无敌区。目标感知遵守战争迷雾与情报规则，不能直接遍历全组敌人后全部“发现”。

阶段 B：隔层直射。独立建立逻辑空间 (x,z,level*层高)、楼板/屋顶/墙/洞口的遮挡模型。确定楼梯是否仅通行，是否也有可射击洞口；行走图与视线图不必相同。三维线段逐段经过各层，检测楼板、墙和开口，射程按约定距离算，命中与掩体在实际所在层求值。

射击流程需要同时处理目标选择、瞄准/射线、命中概率、弹道推进、拦截、掩体/盾牌、友伤与命中层。不得只移除 Verb 的跨图检查或在目标层直接造伤害。可以自建跨层弹体控制器或受控的分段弹道；跨边界保留发射者、目标、速度/进度与已命中状态，避免复制弹体导致双重伤害。

阶段 C：爆炸、穿透、迫击炮、近战高差、特殊能力与垂直坠落。爆炸按三维距离、楼板遮挡及分层投影传播，每个实体只处理一次；不能在各层相同坐标各生成一个满额爆炸。地板/洞口变化应失效视线和通行缓存。CE、护盾和复杂弹药各走兼容适配，初版不承诺支持。

### 高处瞄准低处：显示、点选与自动选敌

2026-10-16 补充。原版事实：Targeter.CurrentTargetUnderMouse 通过 GenUI.TargetsAtMouse 获取候选；后者调用 TargetsAt。GenUI.ThingsUnderMouse 枚举 Find.CurrentMap 的 mapPawns、thingGrid 和特定选择矩形对象；回调目标为 LocalTargetInfo。因此额外画出其他楼层，并不会自动扩展鼠标命中或保留远程格子的地图身份。

AttackTargetFinder.CanSee 使用 seer.Map 做视线和探身检查；GetShootingTargetScore 使用水平距离、searcher.Thing.Map 的掩体和友伤等评分。不能把这些单图计算直接应用于不同层的坐标。

建议把四个概念分开：casterMap 是射手所在图；viewMap 是当前显示图；targetMap 是目标所在图；逻辑空间包含真实层高与枪口/目标高度。更换 viewMap 不移动射手。射击上下文自有保存 caster 引用、武器/Verb 身份、目标与输入状态，不能默认原版 Targeter 在地图切换、选择变化后仍保持有效。

第一版 UI：选中二层射手 → 进入跨层瞄准模式 → 切换一层视图 → 点选敌人 → 预览射线与阻挡原因 → 确认命令。射手始终在二层，UI 显示其名字和来源层；命令带 Thing 引用及地图身份，地面目标则明确带 Map+Cell。射手死亡、换武器、被取消或目标换图时复核/退出。

后续 UI：按需渲染当前层及通过洞口、边缘可见的下层部分，或在战术模式显示已知目标轮廓。可使用遮罩、剖切或单独叠加绘制；这是显示合成，不把目标重新 Spawn 到当前 Map。单 Map 坐标带的 Waylith/IsoRim 绘制、Section 位移和鼠标变换已有源码证据，见 [IsoRim 参考](multilayer-reference-isorim.md)；多 Map 合成/遮罩仍属另一渲染实现分支，不能直接套旧 Unity 多相机或同 Map IFloorLayout。

多层目标拾取由自有命中服务处理：屏幕坐标 → 各可选层的逆投影/候选显示范围 → 目标几何命中 → 目标列表。固定对齐且俯视投影时，各层可共享 x/z；若显示有层偏移或视差，必须使用对应逆变换。命中规则与屏幕绘制一致，叠在同一位置的不同层目标用层筛选、Tab 循环或候选菜单消歧，悬停明确标注层号；不能按跨图 IntVec3 距离随意选第一个。

显示可见、已被发现、允许点选、物理可射击是不同状态。剖切查看楼下不授予射手穿楼板的能力，战术轮廓也不应泄露未知敌人。可允许选中已知但当前受阻目标，在预览中显示“楼板遮挡/需移动”；下令后是否移动到射击位置应由命令模式明确决定。

统一校验服务输入射手、目标和武器，输出可射击性、阻挡层/物体、距离、掩体及分段弹道。使用 (x,z,height) 中的枪口与目标高度，检查线段穿过楼板平面的位置是否落在实体楼板、洞口或建筑外；高处靠外沿可能向下射击，完整楼板内部一般被挡。还需单独定义女儿墙、探身和武器俯仰限制。不能因为目标在下层就允许射击，也不能因为中间层存在楼板就一概阻挡。

自动选敌不依赖显示哪层：按射手能力和情报，收集楼层组内空间近邻候选，先过滤敌我、感知和三维射程，再复用上述校验；以威胁、命中机会、友伤和目标保持策略评分。超出视线但可追击的目标进入移动/找射击位置逻辑。玩家点选、自动攻击、敌人和炮塔使用同一空间规则，并在开火时重新验证，避免只有玩家能够跨层射击。

## 跨层建造：下层屋顶就是上层楼面的结构基础

用户确定的规则：高层只能在紧邻低层的屋顶上建造。固定对齐楼层中，对任意高层 L>0，建筑实际占地的每个格子 c 都必须满足：L-1 层对应格子有已完成且仍有效的屋顶；随后还要通过本层原版建造条件。只检查建筑中心点不够。屋顶蓝图、规划区和待施工任务不能充当已完成的支撑。

空间关系：一层自然地面承载一层建筑；一层屋顶形成二层楼面；二层屋顶形成三层楼面。楼层 Map 可以有完整尺寸，但没有下层屋顶的区域是空洞，不能因默认生成泥土/岩石地面而成为可走可建区域。全局层高、x/z 对齐和格子映射必须稳定。

同一块结构面从下方看是屋顶，从上方看是楼面。建议以“下层屋顶 + 自有楼板元数据”为结构事实来源，上层基础地形是派生表示；上层木地板、地毯等饰面另行保存。铺设或拆除饰面不会创造或移除结构支撑，不能靠铺地板向空中扩建。屋顶材料/建造成本与上层饰面成本分开，避免一块楼板被双重收费或拆除时双重返还。

屋顶是必要条件；允许哪些 RoofDef、是否有承载等级属于额外玩法规则。用户尚未要求重量模拟，不应默认引入逐建筑重量计算。人工顶、薄岩顶、厚岩顶的可用策略需显式配置；厚岩顶若代表连续山体，不能仅复制一块可行走地形就把上方整层山体当成空气房间。下层屋顶存在也不表示上层有自己的屋顶，上层可先是露台，之后再盖顶继续向上扩展。

### 建造流程与复核

1. 在下层建墙/柱及屋顶，按原版规则完成屋顶。
2. 屋顶变化更新对应上层的结构许可。若采用“屋顶自动成为可走楼面”，同步生成派生地形；若采用“已有屋顶后另建结构楼板”，先允许施工，楼板完成后才成为可走楼面。两种模式分别管理成本与拆除，不能混用。
3. 玩家切到上层画蓝图；无支撑格标红，显示“下层缺少屋顶”。多格建筑逐格验证。
4. 多 Map 分支由跨层协调器运送材料和施工 Pawn 至上层施工点，抵达后创建本层建造 Job；单 Map 分支可保留同一原版供料/施工 Job，以拼接路径上下楼。第一版不增加从下方隔层伸手施工。
5. 蓝图转框架、运料、开始施工及完工前再次验证支撑与工作位置。支撑在途中失效时停止供料和施工，释放声明并进入安全恢复。
6. 若允许提前规划，未支撑位置只能保存自有规划意图，依赖下层屋顶完成后再生成可执行蓝图；不能把规划直接视为可施工楼面。

建造合法性、可站立/可达性和供料分别判断：有屋顶但没有楼梯，表示结构合法而施工暂不可达。入口及落脚点也必须有有效楼面；楼梯井的洞口、楼梯实体与邻接平台由专门的连接器规则处理，不能对普通建筑开放整片无支撑格。

### 拆顶、塌顶与结构依赖

必须覆盖主动拆顶、拆掉承顶墙、爆炸/其他 mod 移除屋顶和读档重建。移除下层屋顶后，上层基础楼面失效；预览变红还不够，已有蓝图、框架、建筑、物品和 Pawn 都有处理需求。

建议首版对“上层有建筑/框架/物品/Pawn”的屋顶禁止普通主动拆除并显示依赖对象，先支持搬空再拆；这是建议的初版规则，不是用户已经选定的塌落玩法。敌袭和承顶墙损毁仍可能导致支撑丢失，不能依赖 UI 禁拆保证稳定。非主动失效至少立即封锁通行与施工、取消相关预订，并执行明确的坠落/损毁或临时安置协议；有完整恢复逻辑前不要宣称结构失效功能完成。

完整玩法可实现向下坠落和上层建筑损毁，并重新检查其原先支撑的更高层屋顶；用结构失效队列传播，按稳定顺序批处理、去重和限制单次工作量，避免事件回调递归、重复伤害或重复返还。坠落合法落点、层间洞口、Pawn 伤害及下层碰撞均需独立设计，不应照搬原版单层落顶伤害。

屋顶变化事件仅加入待处理队列，不在 RoofChanged 同步回调中递归改多张图。提交结构变更时同步失效导航、任务与弹道结果，保证待处理缺口不会被当作安全楼面。未加载上层时保存结构版本，生成/加载后重建；不要每建一个屋顶格就强制生成整张新 Map。读档时以实际屋顶和保存的结构信息核对派生楼面，避免凭空补出已拆的支撑。

- GenConstruct.CanBuildOnTerrain 按旋转后的实际占地检查 TerrainAffordance；无 affordance 需求的定义可直接通过，因此自有“必须有下层屋顶”检查不能仅靠给空洞地形移除 Light/Heavy 实现。TerrainCanSupport 也只检查传入地图的支撑条件。

- RoofDef 的当前字段包含 canCollapse、isNatural、isThickRoof，没有现成的上层建筑重量/楼面承载字段。原版 Roofs.xml 提供 RoofConstructed、RoofRockThin、RoofRockThick；FloorBase 的 affordances 和 BuildingBase 的 terrainAffordanceNeeded 是本层地形条件的参考。
- 原版 RoofCollapseCellsFinder 接口接收单张 Map；本次只读取 CheckAndRemoveCollpsingRoofs、RemoveBulkCollapsingRoofs 的目标方法体，未宣称原版可完成跨层连锁坍塌。

新增验收：上层无默认实地；部分屋顶及多格建筑；屋顶蓝图不能承载；饰面拆铺不改变支撑；有楼面无入口；施工中失去屋顶；拆承顶墙；多层连锁失效；楼梯洞口；未生成上层的屋顶变化；存档重启后楼面一致；事件与旁路修改均不留下幽灵楼面。上述仍为设计，未实现或游戏内验证。

## 多层世界语义与性能

需要明确：楼板与下层屋顶的关联、洞口/支撑/塌落、采光、温度、天气与室内、跨层电力/管线/火/气体。先让各层保留本层系统，仅经明确连接器耦合；不要全局合并房间或电网。

殖民地财富、资源计数、故事叙述、袭击入口、商队和任务需要按楼层组定义聚合与事件归属；原版 WealthWatcher.ForceRecount 已递归加入 sourceMap 关联的 PocketMap 财富，自有汇总必须避免重复。不能简单把每层都设成独立玩家基地然后假设故事系统自然正确。地图移除必须先撤销任务、安置实体并断开连接。

128 是整个游戏 Map 总额度，含其他殖民地、任务和 pocket map。应按实际使用生成楼层、预留余量，并显示可用额度；不建议首版 patch 全局上限。没有读档/卸载协议前，不要把有 Pawn 的楼层卸载来省额度。

默认渲染当前层；跨层瞄准时按需叠加下层的局部画面或已知目标。非当前层仍按原版模拟，不能冻结有任务/战斗的层。远程候选按工作类型和层维护索引，分 Pawn 错峰扫描与事件失效；先粗筛再做少量路径精算。原版 1.7 PathFinder 已有异步批处理，不要从任意工作线程访问地图或让它承担未经设计的跨图路径。

测量 TPS、各地图模拟耗时、分配与 GC、每次任务扫描和路径请求数、转移重试和无进展次数。用相同 Pawn/地图/速度比较原版多图、仅启用楼层框架、启用跨层调度，不能凭图搜索复杂度估计实际收益。

## 存档与失败恢复

已有 Map/Pawn/Thing 用 Scribe_References；Def 用 Scribe_Defs；自有任务、连接数据与声明状态按所有权保存。地图仍由原版持有与保存，不在组件里 Deep 一份。路线、Region 和候选缓存不保存，PostLoadInit 后重建。

持久化 dataVersion、楼层关系、连接器、任务意图/阶段和必要的运输所有权。读档后等交叉引用完成，核对 Pawn 实际地图、携带物和资源；重建声明时先对照原版 reservation，再逐步恢复，禁止直接恢复旧路径或吞掉缺失目标。

第一版预期有新增持久类型，不能承诺中途移除 mod 安全。撤销支持需专门的拆层、安置与清理流程。

原生地下 elevation 网格为 1；Underground_RocksFromGrid、MapGenCavesUtility 的闭合洞穴算法、矿簇选择/形状助手及 CaveHives 可复用于单 Map 地下坐标带。只绑定目标带与独立随机作用域，不对已有整图重跑 GenerateContentsIntoMap；后者会清工作数据并吞掉单个 GenStep 异常。

虫灾不是生成虫巢的同一个入口。InfestationCellFinder 还检查迷雾、厚岩顶、温度、空间和殖民建筑距离。CellFinderUtility 的平面距离网格及周围岩体/无顶扫描必须隔离到实际楼层，不能把存储带间距当作地理距离。

增加地下层时，物理高度必须独立于稳定存储带 ID；旧坐标带只追加，不前插搬家。原生 RoughHewn 石面的 natural 标记不能作为唯一地质分类，需核对岩体 naturalTerrain/leaveTerrain 及平滑地形关联。撤销事务新增岩体可用原生 WillReplace 避免逐块触发迷雾洪泛和塌顶扫描；不用于正常玩家开采。
