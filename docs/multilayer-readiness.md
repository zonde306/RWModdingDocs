# 多层 mod 调研收口：原始需求、推荐路线与实施清单

核对日期：2026-10-16。目标是为 RimWorld 1.7 的多层 mod 查清设计与实施所需信息，并更新文档；本轮没有将任务扩大为编写/发布 mod。当前安装为 1.7.4980 rev60，运行时 net10.0 / Waylith，主程序集位于游戏根目录；完整指纹与证据范围见 [sources](sources.md)。

## 调研结论

两条存储路线均有本地实现证据：

- **一层一 Map**：原版层内坐标、Room 与环境自然；跨图转移、工作扫描、预订和连续 Job 需额外协调。[Baal](multilayer-reference-baal.md) 有端点路线、连续 Travel、最终任务续接等具体样本。
- **单 Map 坐标带**：同一 Pawn / Job / 普通预订可以原样跨楼梯，较直接满足连续取料和中间层不丢目标；必须系统处理存储坐标与逻辑空间的差异。[ProjectZ + IsoRim](multilayer-reference-isorim.md) 有生成、路径、绘制/点选、楼板、坍塌和射击源码。

建议第一份技术原型采用单 Map，固定对齐楼层，从三层测试开始，保留可配置的层数与容量策略。该建议基于用户最关心的同 Job 连续工作和俯射，不代表已证明它在大型地图、任意 mod 组合中性能最优。参考 ProjectZ 的 5 层上限是它自己的设置，不是本方案对最终需求的限制。

若原型表明网格面积、生成兼容或空间查询侵入不可接受，则转入多 Map 分支；端点图、逻辑目标、结构面和战斗几何仍可复用，执行/保存适配层不同。最终产品选型需由原型数据确定，而非继续无边界搜索其他 mod。

| 继续补齐必要信息、更新文档 | 电网、设施、房间/气体/火/天气/光照和存档失效边界；统一索引与证据记录 | [公共系统](multilayer-services.md)、[sources](sources.md)、[README](README.md) |

表中“已查明”是源码与设计级结论，不是这些功能已经写成或通过运行测试。原始要求没有要求在本轮建立 mod、运行游戏或发布产物。

## 必须保留的不变量

1. 普通过层不改变最终目标身份；中间层不是完成任务，也不是普通工作重新分派点。
2. 目标失效、断路、需求抢占和玩家取消分别处理；旧请求/回调不得复活已取消任务。
3. 纯格子目标始终可以恢复其楼层/地图；Thing 引用随 Blueprint→Frame→建筑或堆栈变化进行合法重绑定。
4. 拿取、交付、配方消费、产物生成、伤害和退款各自只提交一次；同一 Job / Driver / Map 不由两个所有者重复保存。
5. 每个跨层步执行前确认连接器仍有效；不能只靠清理 Reachability 缓存保护已经持有的路径。
6. 高层普通建筑需要有效楼面且每格下层已有有效屋顶；结构楼板本身从合法邻格施工，避免“先有楼板才能建楼板”的循环条件。
7. 支撑失效立即影响导航/施工/弹道；处理队列尚未完成时，不把缺口继续作为安全格。
8. 存储带间隔永远不是逻辑移动/空气/射线/电力/光照/世界出口；各系统依自己的规则连接。
9. 玩家查看层只影响显示与命令拾取，不改变 AI 的实际位置、地图、任务或物体所有权。
10. 读档恢复业务事实和实体引用，再重建路径、Region、网络和几何缓存；不重播已经提交的副作用。

上述不变量均有对应原版入口/样本缺口和验收场景，而不是要求实现者依靠一个全局距离补丁解决。

## 推荐模块和接入顺序

以下名称是建议服务，不是原版 API。先将状态与查询集中，之后再接入 Harmony，避免补丁彼此假定另一个系统已处理楼层。

| 模块 | 最小职责 |
|---|---|
| LayerLayout / LayerTarget | 稳定楼层、Map/逻辑格映射、间隔拒绝、目标身份与布局版本 |
| ConnectorGraph | 按移动/空气/热/电力/声音分开授权；端点版本、方向、能力与开闭 |
| CrossLayerRouter / PathExecutor | 层内原生路径、完整端点搜索、拼接、请求代次与跨层步最终检查 |
| WorkQueryAdapters | 工作 Thing/格子、食物、床、娱乐、材料/容器、储存优先级和实际交互 |
| StructuralSupportService | 逐格屋顶、楼板/装修层、施工提交、连锁失效与天空列 |
| CombatGeometry / CombatPlanner | 选目标、选射位、LOS/掩体、轨迹/护盾/近战/爆炸和命中保存 |
| UtilityLinks / ExposureService | 电网重建、设施同层、空气/热、天空、天气与游戏/绘制光照 |
| SaveCoordinator / Validation | 原版所有权、自有数据版本、加载顺序、派生状态重建和失效诊断 |

实施顺序：布局/空域与三层路径 → 目标选择/预订与取料 → 严格屋顶施工和失效 → 目标点选与直接跨层射击 → 射位/敌人 AI/护盾爆炸 → 公共系统与长期存档整合。公共系统的接口从起步就保留，不因里程碑顺序而将最终功能删去。

## 运行验证属于下一阶段，不属于已完成结论

文档中的 P0/P1、场景和压力矩阵是未来实现的验收方法，本轮没有伪造测试结果或为通过狭窄测试改变需求。编译成功本身也不能证明这些场景。

必须在独立测试数据目录进行，并在 DLL/Harmony 初始化变化后重启：

- **路径/任务**：1→2→3、同层绕行、必须反向绕层、第 4 个楼梯才通、断路/出口堵塞、移动目标、取消、饥饿/征召抢占。
- **物流/工作**：多次取料、容器材料、多人竞争、堆栈拆并、Blueprint→Frame、产品入库、保存/重启后不丢物复制。
- **结构**：旋转多格建筑、最后施工 tick 拆顶、材料保留/退款、连锁坍塌、携带 Pawn、装修拆除、天空多重遮挡。
- **战斗**：边缘射击与移到射位、洞口/楼板、无步行路线交火、友伤、近战蓄力中换层、个人盾/范围盾、弹丸/延迟引爆/爆炸传播中读档。
- **公共系统**：电缆成环/断线、设施数量/同层、楼板隔气/井口传气、冷热交换、暴露天空、光照数值/画面一致。
- **规模/兼容**：地面尺寸×层数、内存、路径耗时、tick/绘制、河流与生成网格、Core/DLC 组合、明确选定的第三方 Job/武器/管网。

性能收益、实际可支持的层数和大型 mod 组合兼容不能由本地静态调查“证明”。它们是必须通过原型才能获取的证据，不是仍缺一个可以继续反编译查出的确定答案。

## 需要明确的产品参数与默认建议

这些是选择而非待查 API；现在无需阻塞调研或代用户认定：

| 参数 | 建议原型默认值 / 解释 |
|---|---|
| 建造模型 | 已有下层屋顶后建设结构楼板；保留将屋顶自动映射为楼面的替代模式设计 |
| 屋顶类型 | 人工顶先支持；天然薄/厚顶按明确山体策略扩展，不改写厚顶为薄顶 |
| 重量 | 不引入逐建筑质量模拟，用户未要求；仍检查屋顶/支撑有效性 |
| 近战 | 同层 Touch；特殊楼梯近战需显式规则 |
| 射程与精度 | 射程先用明确定义的平面距离；高度增益独立设置，显示与实际一致 |
| 环境 | 实心楼板阻气/挡直射；开放井口按相应图连接；设施默认同层 |
| CE / 第三方框架 | 明确列为待适配组合；关闭自有补丁不等于已经兼容 |

没有在本轮修改玩家配置、启用列表或存档，也没有修改参考项目。设计默认可以在原型阶段调整，但必须保持原始目标：跨层寻路、搬运、工作、战斗与严格屋顶建造。

## 调研完成的边界

本页对照项已由各专题的本地文件、方法体/签名和设计条目逐一核查；格式检查只证明文档可读和链接存在，不充当游戏测试。需要的信息已经落实为：本地参考证据、当前原版关键接口、推荐架构、跨系统契约、具体缺口/风险、保存与失败协议，以及覆盖原始场景的实施验收清单。静态调研阶段可以收口，下一步是实现并验证原型。

这不表示 mod 已完成，也不表示未知第三方内部行为已经穷尽。若后续选择新的框架、具体特殊武器或复杂管网，应在该实现任务中定向核实其额外契约，而不是把所有潜在扩展预先混成无边界调研。
